# 定期檢查活動日期

`data/` 裡有些日期是推估的（標 `"a":1`，畫面顯示「約」），或缺少明年的日期。這份文件說明怎麼找出它們、怎麼查證、怎麼更新。每月由排程自動執行一次，也可以手動照做。

## 1. 產生待查清單

```
npm run pending          # 產生 docs/pending-dates.md（完整清單）與 docs/check-batch.md（本次批次）
```

**每月例行檢查只讀 `docs/check-batch.md`**，不需要讀完整清單或整個 `data/events.json`：

- 批次只含 100 天內開始的項目，最多 60 筆，超過的留到下個月。
- 已依查證方式分組：國定假日每國查一次政府年度假日表、F1 查一次官方賽曆，一次搜尋確認整組。
- 伊斯蘭節日要到前幾天才公告，只有 3 週內的才列入。
- 小型祭典（每月推薦沒提到的祭典、季節）不主動查證，維持「約」，有使用者回報時再修正。國定假日、體育賽事、推薦裡提到的活動照常查證。
- 末尾的「未來屆次」只要搜尋有沒有新消息。

修改資料時用 `grep -n` 找到該筆所在的行再改，不要整個檔案讀進來。範圍可調整：`node scripts/pending-dates.mjs --within 60 --max 40`。

## 1-1. 不是每年舉辦的活動

奧運、亞運、世界盃、大英國協運動會、隔年舉辦的祭典（布魯塞爾花毯節、山王祭本祭）等，下一屆記在 `data/future.json`，不會被當成「缺明年日期」。每次檢查時：

- 查 `future.json` 每一筆的日期是否公布、是否改期或改地點（例如亞運可能從 2030 改到 2031），更新 `d`、`year`、`a`。
- 留意**新決定的主辦地**（例如某屆奧運、世界盃剛選出主辦國），主辦國在 `data/countries.json` 裡就新增一筆。
- `events.json` 裡新增一次性的活動時，記得在 `future.json` 補上它的下一屆。

## 1-2. 行事曆加入新年份時

在 `js/app.js` 的 `YEARS` 加上年份後：

1. `npm run pending` 會把所有每年舉辦、但缺新年份日期的活動列出來，逐一補上（或標 `"a":1` 推估）。
2. 國定假日可用 Python 套件 `holidays` 產生新年份日期，再對照官方公告。
3. `future.json` 裡年份已進入範圍的項目要移到 `events.json`（測試會檢查）。

## 2. 查證來源（依可信度）

1. 主辦單位官網、各國政府公告（國定假日、調休）
2. 各國觀光局官網
3. 大型媒體報導、購票網站
4. 台灣旅行社的團體行程頁（只能當參考，不能單獨作為確認依據）

只有在**官方或主辦單位**公布後才算確認。只有單一非官方來源時，可以修正日期，但保留 `"a":1`。

## 3. 各類型注意事項

| 類型 | 何時會公布 | 處理方式 |
|---|---|---|
| 伊斯蘭節日（開齋節、宰牲節、齋月、先知誕辰、回曆新年） | 依月亮觀測，通常前一天到前幾天才確定 | 只有在當地政府正式公告後才拿掉 `a`；提前幾個月無法確認，不必反覆查 |
| 中國調休安排 | 國務院約每年 11 月公布隔年 | 公布後更新 `CN` 各假日的 2027 範圍並拿掉 `a` |
| 農曆、佛曆節日（水燈節、送水節、衛塞節、Poya 等） | 各國政府通常前一年公布 | 依當地政府年度假日表確認 |
| 祭典、聖誕市集、燈節 | 主辦單位約 2～6 個月前公布 | 查官網 |
| 體育賽事 | F1 賽曆前一年秋季公布，但仍可能調整；馬拉松、網球通常前一年公布 | 有官方賽曆後拿掉 `a` |
| 相撲本場所 | 日本相撲協會約前一年公布 | 查日本相撲協會官網 |

## 4. 修改資料

- 每年固定、只是當年未確認（`"d"` 加 `"a":1`）：確認某一年的日期後，改成 `"y": {"2026": "...", "2027": "..."}`，已確認的年份照官方日期填；兩年都確認才拿掉 `"a"`。
- 已經是 `"y"` 的：直接改日期，全部年份都確認後拿掉 `"a"`。
- 缺明年日期：在 `"y"` 補上該年；未確認就加 `"a":1`。
- 活動停辦或改期：改日期，並在 `"x"` 說明；停辦的整年刪除該年份。
- 每月推薦 `data/picks.json` 裡的文字如果寫到這些日期，一起修正。

## 5. 驗證與發布

```
npm run build && npm test && npm run pending
git add -A && git commit -m "Update confirmed event dates (YYYY-MM)"
git push origin main && git push origin main:gh-pages
```

測試全部通過才能推送。推送後確認線上檔案與 repo 一致（`curl` 比對 `data/events.json`）。

## 6. 回報

列出這次確認或修改的活動（舊日期 → 新日期、來源網址），以及查不到、需要人工判斷的項目。沒有任何變更時不要提交。
